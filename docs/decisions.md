# Decisions log

Decisions made while building the "Next build steps" in `docs/plan.md`, newest last. Each says who decided (user = the product owner; build = made while building, open to change).

## Step C: room groups, gateway runtime (2026-09-26)

**From the user**

1. A wall is opened or closed by a person on the panel, from a **Room linking** menu. (The portal control page can do it too; a sensor is later.)
2. What happens when a wall opens or closes is **set in the portal, in the group settings**, per wall.
3. A group is **deployed as one action**: its rooms first, then its combined rooms.

**Made while building**

| #    | Decision                                                                                                                                                                                                                                                                                           | Why                                                                                                                                                           |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C-1  | Open and close settings are per **wall** (divider), not per group. Four choices: **off**, **on**, **follow** (on if the space it came from was on, else off), **restore** (what that space was doing last time it was live). Defaults: opening = follow, closing = off                             | Matches the proposal the user confirmed; per wall is unambiguous because only one wall changes at a time                                                      |
| C-2  | The wall's setting applies to every **new space** the change creates: the combined room that goes live on open, and each room or smaller combined room that becomes active on close                                                                                                                | One rule for both directions, no special cases                                                                                                                |
| C-3  | New columns `RoomDivider.onOpen`, `onClose`, `open` (additive migration `20260926120000_divider_actions`). `open` is only the last state the gateway reported; the gateway owns the truth                                                                                                          | Working rule: gateway state survives restarts and works offline                                                                                               |
| C-4  | The protocol carries groups in `ConfigResponse.groups` and open walls in `HeartbeatRequest.dividers`. Both default to empty, so gateways in the field keep working and the config version is unchanged for a gateway with no groups                                                                | Protocol stays version 1; old fields (`combinations`) are still tolerated until step D                                                                        |
| C-5  | A group is only sent to a gateway when **all** its ordinary rooms run on it                                                                                                                                                                                                                        | Rooms in a group are controlled together                                                                                                                      |
| C-6  | Applying the migration to the shared database was **not** done by the build: the permission check refused it as a production deploy. It must be run by the user (`pnpm --filter @kestrel/db exec prisma migrate deploy`) before the release PR to `main`                                           | Previews and production share `kestrel-dev`                                                                                                                   |
| C-7  | A suspended room stops **commanding** its devices (panel, triggers, signal detect, auto-off and timers are all ignored) but keeps its device connections and polling open                                                                                                                          | Simple and safe for the devices that allow several connections. Devices that allow only one connection would need the suspended room to disconnect: not built |
| C-8  | Resuming a room drops what it believed it was doing (activity, overlays) but re-reads the devices, so if the displays are on it comes back "on" with no activity chosen. Then the wall's setting runs                                                                                              | Someone else drove the devices meanwhile                                                                                                                      |
| C-9  | Opening a wall is **refused** if the combined room it would create is not running on the gateway (log, and the panel greys the wall out as "not available"). Closing is always possible                                                                                                            | Otherwise the joined rooms would have nothing running them                                                                                                    |
| C-10 | What a suspended room was doing (for **restore**) is kept in memory only. After a gateway restart, restore falls back to off                                                                                                                                                                       | Not worth persisting device activity across restarts yet                                                                                                      |
| C-11 | The gateway no longer runs old-style combinations: `CombineCoordinator` and its tests are gone and it sends `combinations: []`. The old panel intent, bar, protocol fields and table are removed in step D                                                                                         | Keeps C reviewable; nothing in the field depends on them running                                                                                              |
| C-12 | A panel shows and controls **the room that is running its space**: itself, or the combined room while walls are open. Panel access (PIN, trusted IPs) and branding still come from the panel's own room                                                                                            | A person in Room A sees the combined room's controls with Room A's PIN rules                                                                                  |
| C-13 | The Room linking menu lists the walls that touch the space the panel controls (its own walls and the walls of whatever is joined to it), open or closed                                                                                                                                            | Lets someone in a joined space also close the far wall                                                                                                        |
| C-14 | No telemetry event for walls moving yet (a new event type would be rejected by an older cloud). Wall state reaches the cloud through the heartbeat                                                                                                                                                 | Deploy order safety                                                                                                                                           |
| C-15 | The **Link rooms** button is on the top bar for every room in a group, **including the off screen**, and the portal control page and phone page get it for free (they render the same panel)                                                                                                       | Rooms are usually linked before the room is started                                                                                                           |
| C-16 | The menu speaks about **combining the rooms' AV systems**, not walls: "Combine with Room B" / "Linked with Room B" and Combine / Separate buttons, asking first. It lists one choice per neighbour (from the wall's rooms not already in the space). Walls are a dev-side idea (group editor only) | **User decision** (2026-09-26): the language transfers better for the people in the room                                                                      |
| C-17 | Moving a wall from the portal or a phone is always written to the activity log (`wall.set`), unlike volume nudges                                                                                                                                                                                  | It affects several rooms                                                                                                                                      |
| C-18 | The group editor shows "Open now" against a wall the gateway last reported open                                                                                                                                                                                                                    | Lets a dev see the rooms are joined                                                                                                                           |
